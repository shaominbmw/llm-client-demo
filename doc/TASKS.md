## 第 1 层｜LLM 应用基础

### 1.1 统一 ChatClient `[x]` ✅ 2026-11-21

- [x] `LlmClient` 接口（`chat` / `stream`）
- [x] `OpenAiCompatibleClient` 单一实现，覆盖 4 家厂商
- [x] `LlmClientRegistry` 按名字分发 + 默认兜底
- [x] YAML 配置 + `${ENV}` 占位符
- [x] 切换模型只改配置，Java 零改动

**验收**：改 `llm.default` → 重启 → 模型切换成功，代码未动。
**状态**：已验收（deepseek ⇄ qwen 双向验证）

### 1.2 参数控制 `[~]`

- [x] `temperature`（0~2）
- [x] `max_tokens`（含厂商级默认值）
- [ ] `top_p`（核采样）
- [ ] `stop`（停止序列）
- [ ] 能解释「同一 prompt 两次结果不同」的原因，并调稳定

**验收**：能说出 `temperature` 和 `top_p` 的区别，以及什么场景只调其中一个。

### 1.3 结构化输出 `[ ]`

- [ ] `response_format: json_object` 支持
- [ ] `response_format: json_schema`（严格模式，按厂商能力降级）
- [ ] 解析容错：去掉 ` ```json ` 围栏、前后废话
- [ ] 解析失败自动重试一次（带错误信息给模型）
- [ ] 用 Jackson 反序列化成 record
- [ ] 至少一条业务校验（字段非空 / 枚举合法）

**验收**：同一段自然语言 → 稳定输出可反序列化的对象，连续跑 10 次不崩。
**为什么重要**：这是 RAG 抽取和 Agent 工具调用的地基。

### 1.4 Function Calling `[ ]`

- [ ] 工具定义（name / description / parameters schema）
- [ ] `tools` 参数传入 + `tool_calls` 解析
- [ ] 工具执行 + 结果回填 + 二次请求
- [ ] 多工具并行调用的处理
- [ ] 工具不存在 / 参数非法时的兜底

**验收**：写一个「查天气 + 查时间」的双工具 Agent，模型能自己选对工具并填对参数。

### 1.5 流式输出 SSE `[x]` ✅ 2026-11-21

- [x] `Consumer<String>` 回调
- [x] `data:` 行解析 + `[DONE]` 终止
- [x] `stream_options.include_usage` 拿 usage
- [x] 聚合结果与回调一致（有测试）
- [x] TTFT 统计

**验收**：实测 TTFT 612 ms（deepseek-chat）。
**遗留**：推理模型的 `reasoning_content` 未展示 → 见 1.7

### 1.6 错误处理 `[x]` ✅ 2026-11-21

- [x] 7 种 `Kind`：AUTH / QUOTA_EXCEEDED / RATE_LIMIT / TIMEOUT / CONTENT_FILTER / BAD_REQUEST / SERVER_ERROR
- [x] `retryable()` 判定
- [x] 响应体关键字优先于状态码
- [x] 404 带 base-url 提示
- [ ] 真正的重试循环（目前只有判定，没有执行）

**验收**：403+quota 映射成 `QUOTA_EXCEEDED` 而非 `AUTH`（有测试）。
