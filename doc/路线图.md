## 1. 能力地图：5 层，每层都有「过关标准」

不要问「我要学多久」，要问「我能不能做到这一栏」。**做到就走，别恋战。**

### 第 1 层｜LLM 应用基础（W1–W4，约 3 周）

| 学什么 | 过关标准（做不到就别说学过） |
|---|---|
| 国产模型 API：DeepSeek / 通义 Qwen / 智谱 GLM / 豆包 | 能封装一个统一 `ChatClient`，切换模型只改配置 |
| 参数：temperature / top_p / max_tokens / stop | 能解释「为什么同一 prompt 两次结果不同」，并能调稳定 |
| **结构化输出（JSON Schema 约束）** | 能让模型稳定输出可被 `Jackson` 反序列化的对象，失败率 < 2% |
| **Function Calling / Tool Use** | 能手写一个工具注册+分发器，模型自动选工具并填参数 |
| 流式输出 SSE | 能在 Spring Boot 里做打字机效果，前端能断线重连 |
| 错误处理 | 超时、429 限流、内容审核拦截、返回空 —— 四种都有兜底 |
| Prompt 四段式 | 角色 / 任务 / 约束 / 示例，能写出一份别人复用不出错的 prompt |

> **认知转变（最重要）**：别把 LLM 当"聊天机器人"，把它当**一个不稳定、会自信胡说、但泛化能力极强的远程函数**。凡是调用它，就要想：超时怎么办？失败了重试吗？结果怎么校验？——这个视角一转，后面全通。

**技术选型**：`LangChain4j`（生态全，推荐）或 `Spring AI`（你 Spring 熟就更顺）。**二选一，不要都学。**

### 第 2 层｜RAG（W5–W9，约 4 周）★ 企业付费意愿最强

| 学什么 | 过关标准 |
|---|---|
| 文档解析 | PDF（含扫描件 OCR）/ Word / Excel / PPT 都能进管道，表格不丢结构 |
| 清洗 | 去页眉页脚、去目录、合并断行、识别章节层级 |
| **切分策略** | 能说清定长 / 语义 / 父子块的取舍，并按文档类型选对 |
| Embedding | `bge-m3` 本地跑通（或 API），知道向量维度与归一化 |
| 向量库 | **pgvector** 建表 + HNSW 索引 + 增删改查（首选，运维最简单） |
| **混合检索** | 向量 + BM25 双路召回，能说清各自擅长什么 |

> 无锡制造业对口场景：**设备维修手册、工艺文件、质检标准、SOP、安全规程查询**。这就是你的第一桶金。

### 第 4 层｜工程化（W14–W18，约 4 周）★★ 分水岭，决定你是 15k 还是 30k

## 3. 三个项目的详细需求文档

> 原则：**每个项目都要能解决一个真实的、老板愿意付钱的问题**，而且是你在无锡能接触到的问题。

### 项目一：设备维修手册 RAG 问答系统

**背景（写进简历的问题陈述）**
工厂设备手册动辄上千页，维修工排查一个故障平均要翻 30–40 分钟，老师傅经验带不走。

**功能清单**
- MVP：文档上传（PDF/Word）→ 自动解析入库 → 自然语言提问 → 答案带原文页码引用
- 加分：多文档混合检索、按设备型号过滤、答案附「相关图纸/表格」、无答案时拒答
- 加分：离线私有化（W18 补）

**技术选型**：Spring Boot 3 + LangChain4j + pgvector + bge-m3 + bge-reranker-v2-m3 + Qwen2.5-14B（Ollama）

**验收标准**
- 50 条真实问题，Top-3 命中率 ≥ 80%
- 每个答案都有可点击的原文出处
- 单次问答成本 < 0.05 元
- 断网可运行

**简历写法**
> 设备知识库 AI 问答系统（独立开发）
> - 问题：2000+ 页维修手册，故障排查平均 40 分钟
> - 方案：LangChain4j + pgvector 混合检索（向量+BM25）+ bge-reranker 重排 + 引用溯源抑制幻觉
> - 效果：Top-3 命中率 82%，单次问答 0.03 元，Qwen2.5-14B 离线部署满足数据不出厂要求
> - 难点：扫描件与表格解析、长文档切分、离线量化部署

### 项目二：质检报告自动生成 Agent

**背景**
质检员每天要对着标准逐项填报告，重复劳动，且格式不统一、易漏项。

**功能清单**
- MVP：输入质检数据（Excel）+ 现场照片 + 标准文件 → 自动比对 → 生成结构化报告 → 人工确认后导出 Word
- 加分：不合格项自动高亮 + 给出可能原因、历史相似案例引用、批量处理
- 关键设计：**必须有人工确认环节（HITL）**，AI 不直接出最终结论

**技术选型**：LangChain4j Agent + 工具调用（读 Excel / 查标准 / 生成文档）+ 结构化输出 + POI 导出 + Dify 作为可交付的流程版本

**验收标准**
- 一份报告生成时间从 20 分钟降到 2 分钟
- 必填项漏项率 0
- 工具调用失败有降级路径，不会整条流程崩

**简历写法**
> 质检报告生成 Agent（独立开发）
> - 问题：质检员日均 30 份报告，单份 20 分钟，格式不统一
> - 方案：Agent 编排 + 工具调用（读数据/查标准/生成文档）+ 人工确认环节
> - 效果：单份 2 分钟，漏项率 0；失败降级 + 最大步数限制杜绝死循环
> - 难点：标准文件结构化、多工具参数校验、人工介入时机设计

### 项目三：工厂经营分析 Agent（自然语言问数）

**背景**
老板想看「这个月哪个车间成本超了」，要等 IT 排期做报表，一周起步。

**功能清单**
- MVP：自然语言提问 → 生成 SQL → 查询 → 结果 + 图表 + 一句话结论
- 加分：多 Agent（查数 / 分析 / 写报告）、追问上下文、异常自动预警、权限隔离（车间主任只能看自己车间）
- 关键设计：**SQL 只读、白名单表、行级权限、注入防护**

**技术选型**：LangChain4j 多 Agent + Text-to-SQL + 元数据 Schema 注入 + ECharts + Langfuse 追踪

**验收标准**
- 50 条业务问题，SQL 正确率 ≥ 75%
- 危险 SQL（DROP/DELETE/跨表越权）100% 拦截
- 每条回答可追溯到执行了哪条 SQL

**简历写法**
> 工厂经营分析 Agent（独立开发）
> - 问题：老板要的经营报表依赖 IT 排期，平均 5 个工作日
> - 方案：多 Agent（查数/分析/成文）+ Text-to-SQL + Schema 注入 + 只读白名单与行级权限
> - 效果：50 条业务问题 SQL 正确率 78%，报表从 5 天到 30 秒，越权 SQL 100% 拦截
> - 难点：中文业务口径到 SQL 的映射、多表 join 歧义、权限与安全边界

## 4. 简历改造指南

### 4.1 现在简历的三个问题

1. **全是「负责 XX 模块开发」**——描述职责，不描述结果。HR 看不出你和别人有什么区别。
2. **「外包」两个字太显眼**——写成「驻场于滴滴（客户方）」，重点讲系统规模和你的角色。
3. **没有 AI 关键词**——ATS 机筛直接过滤。至少要有：LLM、RAG、Agent、向量检索、Prompt、私有化部署、Eval。

### 4.2 改写模板（每条经历都用这个结构）

```
项目名（角色）
- 问题：一句话说清业务痛点，带数字
- 方案：用了什么技术，为什么这么选（一句）
- 效果：量化指标（准确率 / 耗时 / 成本 / 覆盖量）
- 难点：一个真实的技术难点 + 你怎么解的
```

### 4.3 「成人本科」怎么处理

- 教育栏写：**本科 · 计算机科学与技术 · 学士学位**，不主动标注「成人/自考」。
- HR 问起如实说，不解释、不辩解。
- **双证齐全是你相对大专的最大增量**，一定要把「学位」写出来（国企、落户、签证才认）。

### 4.4 被问「第一学历是大专吧」的标准答法

> 「对。我 8 年一直在写生产系统，最近在做一个设备知识库的 RAG 项目，我讲讲这个？」

不解释、不自嘲、不铺垫。**这里真正的杀伤力不是学历，是你的自卑感。** 你越平静，这事越不存在。

### 4.5 被问「34 岁为什么转 AI」

> 「不是转，是加。我 8 年 Java 的工程能力是底座，AI 是让这个底座能解决以前解决不了的问题。我这个年纪最大的优势是能跟工厂老板把需求聊明白，25 岁的工程师聊不了。」

### 8.1 你每周日晚上 21:00 前发我三条


### 8.2 我每周给你三样

1. **验收**：对照本周过关标准，判定「过了 / 没过 / 假过」。
2. **纠偏**：你在浪费时间的地方，我直接叫停。

### 8.3 我们之间的规矩

- **卡住超过 2 小时就问我**，别自己耗一整天。你的时间比我的回答贵。
- **我不替你写业务代码**，但会给架构、给选型、给你 code review 的重点。
- **你可以随时打断计划**：如果无锡本地出现一个真实客户需求，优先做那个，计划可以改。
- **允许你失败，不允许你消失。** 断更两周以上，我会先把节奏拉回来，不问责。

## 9. 风险与止损

**必须守住的三条红线**
1. 不辞职（外包虽然不稳，但现金流是转型的氧气）。
2. 不借钱、不投入超过 1 万元。
3. 不买超过 500 元的课，不为「训练营」付智商税。

**三个真实风险**
- **时间被加班吃掉**：外包项目忙起来会连续几周没进度。对策：把学习时间放在早上，晚上容易被工作侵占。
- **学完不敢卖**：这是最常见的死法。对策：W19 就开始 demo，不要等「完美」。
- **无锡岗位少**：本地 AI 岗确实不多。对策：A 档打底 + B 档提价 + D 档兜底，三条腿走路。

**止损判断**
- 如果 W12 还没做出任何能 demo 的东西 → 不是方向问题，是执行问题，砍掉一切非必要学习。
- 如果 W24 投了 50 家 0 面试 → 是简历/作品集问题，不是能力问题，重做包装。
- 如果面了 10 家全挂在一面 → 把面试录音/复盘给我，逐条改。
