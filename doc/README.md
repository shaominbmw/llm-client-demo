# doc/ 目录说明

> 这里是这个项目的**唯一事实来源**。所有和语雀同步的文档都放在这儿。
>
> 工作流：**在仓库里写 → 提交 git → 拖进语雀**。语雀是镜像，不是主库。

---

## 目录结构

```
doc/
├── README.md            ← 你在这里
├── TASKS.md             ← 任务清单（主入口，每周更新）
├── 路线图.md             ← 24 周学习计划
├── 周记/                 ← 每周一篇，记录完成/卡点/计划
├── 踩坑/                 ← 真实故障记录，四段式
├── 知识卡片/             ← 概念速查，一篇一个概念
├── 项目/                 ← 每个项目一篇，含架构与取舍
└── 面试/                 ← 高频题 + 话术 + 复盘
```

---

## 各类文档的写法约定

### 周记（`周记/`）

文件名：`W{n}-{日期}-{主题}.md`

```markdown
## 本期完成
## 卡点
## 下周计划
```

**要求**：必须有数字（耗时 / 命中率 / token / 测试数）。没有数字的周记等于没写。

---

### 踩坑（`踩坑/`）

文件名：`{序号}-{一句话描述}.md`

```markdown
## 现象        ← 报错原文 + 当时的操作
## 原因        ← 机制层面，不是"我写错了"
## 解决        ← 具体怎么做
## 以后怎么避免  ← 能不能变成校验/测试/默认值
```

**最后一段是分水岭**。只写到「解决」的是操作记录；写到「怎么避免」的才是工程能力。

---

### 知识卡片（`知识卡片/`）

文件名：`{概念名}.md`

```markdown
# 一句话
# 原理 / 格式
# 关键坑
# 自测题
```

**要求**：一篇只讲一个概念，能独立阅读。三个月后翻出来还能看懂。

---

### 项目（`项目/`）

文件名：`P{n}-{项目名}.md`

必须包含：解决什么问题 / 架构 / 跑法 / 测试 / **设计取舍** / 已知限制。

「设计取舍」那一节是面试重点，写的时候想：**如果面试官问"为什么这么设计"，我怎么答**。

## 和语雀的同步

语雀知识库「ai学习」的目录结构与这里一一对应：

| 本地 | 语雀 |
|---|---|
| `doc/路线图.md` | `00 路线图` |
| `doc/周记/` | `01 周记` |
| `doc/踩坑/` | `02 踩坑记录` |
| `doc/知识卡片/` | `03 知识卡片` |
| `doc/项目/` | `04 项目` |
| `doc/面试/` | `05 面试准备` |

**同步方式**：语雀里逐个目录拖入对应文件夹的 `.md` 文件。
语雀不保留层级，所以要「进一个目录 → 拖一批」。

⚠️ 语雀是**只读镜像**。要改内容，改这里的文件，然后重新拖一次。
不要在语雀里直接编辑，否则两边会分叉。

---

## 为什么文档要进代码仓库

1. **和代码同生共死**：删了代码还留着文档，或反过来，都是灾难
2. **有版本历史**：能看到一个想法是怎么演变的
3. **面试时可直接展示**：面试官点进仓库，看到 `doc/` 就知道你是有方法的人
4. **不依赖第三方**：语雀改政策、收费、限流，你的东西还在
